# 손동작 인터랙션 기획

작성일: 2026-11-16
브랜치: `feature/hand-tracking`

손을 집중적으로 추적하고, 손동작마다 서로 다른 파티클 효과를 입히는 방향의 기획이다. 구현된 구조와 API는 [DEVELOPMENT.md의 손 추적](DEVELOPMENT.md#손-추적)에 있다.

## 1. 배경: 기존 방식으로 안 되는 이유

지금 상호작용은 두 가지 픽셀 비교에 기대고 있다. 둘 다 사람을 알아보지 않고, 픽셀이 바뀌었는지만 본다.

| 모듈 | 방식 | 판단 기준 |
| --- | --- | --- |
| `MotionDetector` | 프레임 차분. 이전 프레임과 현재 프레임의 밝기를 비교한다 | 8px 칸마다 밝기 차이가 임계값을 넘는 비율 |
| `BackgroundMask` | 배경 차분. `B` 키로 찍어 둔 빈 배경과 현재 프레임을 비교한다 | 색 차이가 임계값을 넘는 영역 |

이 방식으로는 다음을 할 수 없다.

- **손 모양 구분**: 쥐었는지 폈는지, 엄지와 검지를 붙였는지 알 수 없다.
- **멈춘 손 유지**: 프레임 차분은 멈춘 손을 0으로 본다.
- **여러 방향**: 화면 전체에서 방향이 하나만 나온다. 두 손이 반대로 움직이면 서로 상쇄된다.
- **잡음 구분**: 조명 변화, 그림자, 뒤에서 지나가는 사람도 움직임으로 잡힌다.

손동작으로 효과를 나누려면 손가락 관절의 좌표가 있어야 한다.

## 2. 결정 사항

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 언어 | Processing 4 Java Mode 유지 | 기존 코드와 두 컴퓨터(Mac, Windows) 환경을 그대로 쓴다 |
| 추론 실행 | ONNX Runtime Java (`code/` 폴더의 jar) | Python이나 Node 프로세스 없이 스케치 안에서 모델을 돌린다. jar 하나에 Windows x64와 Apple Silicon 네이티브가 들어 있다 |
| 모델 | MediaPipe Hands, opencv_zoo의 ONNX 변환본 (Apache 2.0) | 손가락 관절 21개를 준다. 몸 포즈 모델(MoveNet)은 손목 점 하나만 줘서 부족하다 |
| 거리 | 카메라에서 1 m 안쪽 | 손바닥 검출 모델이 잘 동작하는 범위다. 몸 포즈 모델로 손 위치를 먼저 찾는 보완은 필요 없다 |
| 손 개수 | 양손 동시 추적 | 양손 사이 거리 같은 두 손 효과를 쓰기 위해서다 |
| 기존 움직임 감지 | 유지 | 손이 없을 때의 기본 상호작용과 예비 수단으로 남긴다 |
| 저장소 | jar(약 51 MB)와 모델도 커밋 | 두 컴퓨터가 별도 설치 없이 같은 버전을 쓴다 |

검토했지만 고르지 않은 선택지:

- **OpenCV 공식 Java 바인딩**: 운영체제마다 네이티브 라이브러리를 따로 준비해야 한다.
- **DJL**: 의존성이 무겁고, 처음 실행할 때 엔진을 내려받아 오프라인 전시장에서 다루기 어렵다.
- **Deep Vision for Processing**: 유지보수가 멈춰 Processing 4와 Apple Silicon에서 동작하는지 보장할 수 없다.
- **YOLOv8-pose/seg**: AGPL 라이선스다.
- **깊이 카메라**: 하드웨어가 바뀐다.

## 3. 손동작과 효과 연결

관절 21개로 규칙 기반 판별을 한다. 흔들림을 막기 위해 같은 동작이 몇 프레임 이어질 때만 인정한다.

| 손동작 | 판별 방법 | 효과 |
| --- | --- | --- |
| 집기 (pinch) | 엄지 끝(4)과 검지 끝(8) 사이 거리 / `palmSize` | 집은 지점으로 입자를 끌어모으고, 손가락을 떼면 터지듯 흩어진다 |
| 손바닥 펴기 | 다섯 손가락이 모두 펴짐 | 손바닥 앞의 입자를 밀어내는 바람 |
| 주먹 | 손가락 끝이 손바닥 중심 가까이 모임 | 입자를 한 점에 압축해 가둔다 (기억을 움켜쥠) |
| 검지로 가리키기 | 검지만 펴짐 | 손가락 끝을 따라 청록·보라 네온 궤적을 그린다 |
| V 사인 | 검지와 중지만 펴짐 | 잔상(Echo) 소환 같은 모드 전환 |
| 양손 사이 거리 | 두 손 중심 사이 거리의 변화 | 초상화를 늘리거나 흩뿌리는 정도를 조절한다 |
| 휘두르기 (swipe) | 손목 속도와 방향 | 그 방향으로 입자를 쓸어낸다. 지금의 방향 쓸기를 손 기준으로 바꾼 것이다 |

손가락이 펴졌는지는 손가락 끝이 손목에서 두 번째 마디보다 멀리 있는지로 본다. 기준 거리는 모두 `palmSize`로 나눠서, 손이 카메라에 가깝거나 멀어도 같은 기준이 되게 한다.

## 4. 단계

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | `HandTracker`: 양손 관절 21개 추적, 별도 스레드, `T` 디버그 표시 | 완료. 테스트 사진으로만 검증했고, 실제 카메라 확인은 남았다 |
| 2 | `GestureRecognizer`: 집기·펴기·주먹·가리키기 판별, 디바운스. 측정값만으로 되는 V 사인도 함께 넣었다 | 완료. 테스트 사진과 합성 시험으로만 검증했고, 실제 카메라 확인은 남았다 |
| 3 | `HandEffects`: 손바닥 바람, 검지 가르기와 네온 궤적, 집기 끌어모으기, 주먹 압축, 놓을 때 터뜨리기. `ParticleSystem`에는 밀기·끌어모으기·튕기기 세 가지 범용 힘을 추가 | 완료. 하네스로 물리 동작만 검증했고, 실제 카메라와 화면 확인은 남았다 |
| 4 | 양손 거리, 휘두르기 추가. V 사인에 효과 연결. 잔상(`EchoSystem`)과 네온(`NeonEffects`) 연결 | 예정 |

한 단계의 실행을 실제 카메라로 확인한 뒤 다음 단계로 넘어간다.

## 5. 1단계 검증 결과

2026-11-16, Windows 11, Processing 4.5.7의 JDK 17로 확인했다. 쓴 자료는 MediaPipe 공식 테스트 사진 7장이다.

- 모두 검출됐다. 양손 사진에서는 두 손이 모두 잡혔고, 거꾸로 된 손과 옆으로 누운 손도 관절이 정확했다.
- 640×480 프레임에서 양손을 추적할 때 평균 16 ms, 최악 25 ms가 걸렸다. 카메라 프레임 간격 33 ms 안이다.
- 움직이는 사진을 작업 스레드로 60프레임 넣는 동안 두 손 모두 놓치지 않았고, 번호도 유지됐다.
- 원본(반전 전) 영상에서 모델의 왼손/오른손 원값은 실제 손과 일치했다.

## 6. 남은 확인과 위험

- **실제 카메라**: Mac과 Windows에서 `T`로 추적 상태를 확인한다. 체크리스트는 DEVELOPMENT.md에 있다.
- **Intel Mac**: ONNX Runtime jar에 Intel Mac용 네이티브가 없어 지원하지 않는다.
- **조명**: 배경이 어두운 전시장에서는 정확도가 떨어진다. 손 쪽에 약한 조명을 두는 것을 검토한다.
- **저장소 크기**: jar가 50 MB를 넘어 GitHub에 push할 때 권장 크기 초과 경고가 나온다. push는 된다.
